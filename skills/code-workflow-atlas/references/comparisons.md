# Comparing workflows

Pin both versions and follow equivalent entry points. A classic generator, an agentic editor, and a native-document renderer are separate routes; inspect the relevant path before making feature claims.

For each aligned stage, record what is shared (exact text/function or just similar responsibility), what actually changes, possible effects, and source/runtime evidence. Distinguish verified differences from hypotheses and measured performance.

Compare base templates separately from complete requests. Identical templates can produce different results because of input materials, appended rules, model versions, sampling, parsing, fonts, or renderers. A removed snippet may have a replacement elsewhere: search before calling it a regression.

For fair quality/performance comparisons, fix inputs and execution conditions, save intermediate results, and find the first stage that diverges. A similarity percentage, package version, or architectural difference is not a measured quality or speed result. Use synthetic data for public demos.
